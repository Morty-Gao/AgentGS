\section{Related Work}
\label{sec:related-work}

\subsection{Task Planning and Tool-Dependency Representations for Geoscientific Agents}
\label{sec:related-planning}

For agent task planning, ReAct established a reasoning--action--observation loop as a foundational paradigm~\cite{yao2023react}. ToolPlanner methods support task execution over large tool collections through functional grouping~\cite{wu2024toolplanner,liu2025toolplanner}, while LLM+P and Generalised BDI Planning introduce explicit planning solvers and goal management~\cite{liu2023llmp,meneguzzi2025bdi}. Existing geoscientific agents have adopted these general paradigms: GeoAgent uses a planning--execution--reflection architecture for GIS analysis~\cite{chen2024geoagent}, and Earth-Agent organizes multistep calls to process Earth science data~\cite{feng2026earthagent}. These studies demonstrate the feasibility of multistep tool use in geoscientific agents. Composition across strategies additionally requires an explicit distinction between reusable operations, their dependencies and usage constraints in the original strategy, and concrete implementations.

For tool-dependency representations, SciToolAgent orchestrates scientific tools through a tool knowledge graph~\cite{ding2025scitoolagent}, while HyperAgent constructs a tool hypergraph from input/output schemas and searches for supporting tools~\cite{zhai2026hyperagent}. Whereas these approaches organize relationships directly among tools, we focus on jointly representing operation-level reuse and constraints with strategy provenance in geoscientific tasks. AgentGS follows structured planning and hypergraph representation: shared Capabilities are nodes, Skills are hyperedges, and Capability--Tool mappings link concrete implementations. Dependencies and usage constraints within each Skill are retained, enabling local operations to be reused across strategies, missing branches to be retrieved for plan completion, and plans to be grounded in actual calls.

\subsection{Evaluation of Geoscientific Agents}
\label{sec:related-evaluation}

Existing evaluations fall into three categories according to what they assess, reflecting a progression from knowledge to execution processes. \emph{Geoscientific question-answering benchmarks} assess domain knowledge. GeoBench uses examination-style questions to evaluate geoscientific understanding~\cite{deng2023k2}; EarthSE includes professional questions and open-ended scientific dialogue to assess geoscientific exploration~\cite{xu2025earthse}. Multistep reasoning in these benchmarks takes place at the language level and does not require actual tool calls. \emph{General scientific-agent evaluations} concern code execution and data processing rather than domain-specific tool chains. Systems such as SciToolAgent, GeoAgent, and Earth-Agent demonstrate scientific data processing and analysis through tool use~\cite{feng2026earthagent,ding2025scitoolagent,chen2024geoagent}. Their evaluations have begun to record execution behavior, but task structures remain predominantly question--answer pairs accompanied by code execution. \emph{Multitool orchestration benchmarks} explicitly assess multistep tool use. GeoBenchX requires agents to use geospatial tools for multistage tasks and evaluates results against reference solutions~\cite{krechetova2025geobenchx}. Earth-Bench distinguishes autonomous planning from instruction following and records tool inputs and outputs~\cite{feng2026earthagent}. GeoAgentBench examines invocation order, parameters, and final map artifacts in a GIS sandbox~\cite{yu2026geoagentbench}. GeoNatureAgent Benchmark evaluates multitool analysis and error recovery using real APIs~\cite{diazireland2026geonatureagent}. These benchmarks address multistep invocation and some dependency verification, but differ in task scenarios, tool packaging, and the scope of process checks.

No existing benchmark jointly evaluates the complete orchestration chain---operation selection, tool dependencies, composition across tools, consumption of intermediate artifacts, and final answers---within individual tasks across multiple geoscientific themes. This prevents failures from being attributed to specific stages and limits actionable diagnostic signals. GeoToolEval offers three advantages: (1) coverage of ten geoscientific research-frontier themes, enabling orchestration to be assessed across scenarios; (2) joint evaluation of agreement with reference invocation sequences, actual use of intermediate artifacts, and final answers within the same task, extending assessment from invocation correctness to process completeness; and (3) explicit assessment of necessary-operation completion, allowing failures caused by missing capabilities to be distinguished from execution errors.
