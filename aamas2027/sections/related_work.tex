\section{Related Work}
\label{sec:related-work}
\paragraph{Planning and dependency representations.}
ReAct interleaves reasoning, actions, and observations~\cite{yao2023react}. ToolPlanner methods organize large tool collections~\cite{wu2024toolplanner,liu2025toolplanner}, while LLM+P and Generalised BDI Planning introduce explicit planning and goal management~\cite{liu2023llmp,meneguzzi2025bdi}. GeoAgent and Earth-Agent apply multistep planning to geoscientific analysis~\cite{chen2024geoagent,feng2026earthagent}. These methods establish planning and execution as central components of scientific agents.

Structured dependency representations guide composition. SciToolAgent organizes tools through a knowledge graph~\cite{ding2025scitoolagent}; HyperAgent constructs a tool hypergraph from input/output schemas and searches for supporting tools~\cite{zhai2026hyperagent}. AgentGS organizes shared operations and strategy-specific dependencies separately from tool implementations. Reused operations retain their source prerequisites and permitted tools, so fragments can be combined without adopting an entire strategy. Completion then searches declared branches to connect those fragments. The focus is on preserving strategy knowledge during local reuse, with concrete tool selection following workflow composition.

\paragraph{Geoscientific evaluation.}
GeoBench and EarthSE assess knowledge and scientific exploration without requiring tool execution~\cite{deng2023k2,xu2025earthse}. GeoBenchX evaluates multistage geospatial tasks against reference solutions~\cite{krechetova2025geobenchx}; Earth-Bench distinguishes autonomous planning from instruction following and records tool inputs and outputs~\cite{feng2026earthagent}; GeoAgentBench checks invocation order, parameters, and map artifacts in a GIS sandbox~\cite{yu2026geoagentbench}; and GeoNatureAgent Benchmark tests multitool analysis and recovery with real APIs~\cite{diazireland2026geonatureagent}.

GeoToolEval complements these benchmarks with coverage across ten research themes and scores for answers and tool workflows under common interfaces. This supports comparison across data types and workflow lengths. A reference workflow specifies one implementation, so agreement with its calls is assessed separately from answer correctness. Successful tool calls alone do not establish that downstream operations consumed the intended intermediate results. The annotations and execution records link calls to their inputs and outputs, supporting diagnosis of missing operations and execution errors, including incorrect bindings between otherwise appropriate tools.
