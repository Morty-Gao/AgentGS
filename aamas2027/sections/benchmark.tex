\section{GeoToolEval}
\label{sec:benchmark}
We introduce GeoToolEval by integrating tasks from multiple geoscientific datasets and annotating their reference tool calls under a common set of interfaces. Each task pairs a scientific question with input resources, a reference answer, and a reference workflow, supporting evaluation of both the result and the tool use required to obtain it.

\subsection{Dataset Construction and Coverage}
\label{sec:benchmark-construction}
\label{sec:benchmark-composition}
GeoToolEval combines existing question-answer tasks with tasks derived from scientific data. The former include selected questions from GeoQuestions1089, Earth-Bench~\cite{feng2026earthagent}, and \nolinkurl{habitable_earth_dataset}. We retain their questions and reference answers while mapping the required operations to the registered tool interfaces. For data-derived tasks, questions specify identifiable objects and computational relationships, and reference answers are obtained through the corresponding analysis.

The dataset contains 603 evaluation records across ten research themes, covering resources such as Earth-structure models, mineral inventories, climate observations, remote-sensing imagery, and disaster-event records (Table~\ref{tab:benchmark}; Figure~\ref{fig:geotooleval}a). Of these records, 424 require one reference call, 119 require two or three, and 60 require at least four. Single-step tasks assess basic data access and tool use, while multistep tasks additionally involve operation composition and intermediate results. Counts refer to calls under the registered interfaces; a tool may perform several operations internally. Source details, construction checks, and cross-theme overlap are described in Appendix~\ref{app:dataset-details}.

\subsection{Task Definition and Tool-Call Annotations}
\label{sec:benchmark-design}
\label{sec:task-record}
We represent an evaluation record as
\begin{equation}
\mathcal{E}_i=(q_i,X_i,y_i^{\star},\tau_i^{\star}),
\label{eq:task-record}
\end{equation}
where $q_i$ specifies the scientific question and requested outputs, $X_i$ identifies the input data and resource locators, $y_i^{\star}$ is the reference answer, and $\tau_i^{\star}$ is a reference tool-call sequence. Answer types and format requirements support consistent scoring across numerical, categorical, and structured outputs.

The tool-call annotations identify the tool, arguments, and relevant input/output information for each reference step. They connect the question to a concrete analysis over the supplied resources. For example, a task requesting the number of events satisfying a condition can be annotated as loading an event table, filtering its records, and counting the filtered result. This records the intermediate object needed by the final operation, in addition to the expected count.

The reference workflow provides one implementation under the registered interfaces. It supports comparison of tool coverage and order and helps locate differences in execution. Alternative workflows may also produce a valid answer, so agreement with the reference calls is assessed separately from answer correctness.

\subsection{Evaluation Metrics}
\label{sec:metrics}
Each record is scored in $[0,1]$, and failed tasks remain in the average. Table~\ref{tab:main-results} reports six scores. FAS measures agreement with the reference answer and keeps partial credit. TSF1 measures whether the successful calls cover the reference tools. PAS measures whether the arguments of aligned calls match the reference. TOS measures whether those calls preserve the reference order. ECR measures the share of attempts that are matched successful calls. Quality is their weighted aggregate. Bash-only agents have no tool trace, so only FAS applies to them. Formulas and weights are in Appendix~\ref{app:metric-details}.
