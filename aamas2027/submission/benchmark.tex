\section{GeoToolEval}
\label{sec:benchmark}
GeoToolEval associates answer evaluation and execution-process analysis within each task. For example, statistics must consume the composite raster rather than the original images; successful calls alone do not establish the requested analysis. Its records contain a natural-language question, input resources, a reference answer and answer type, and reference tool calls. Single-step tasks assess data location, parameter determination, and basic invocation; multistep tasks examine operation composition, dependencies, and use of intermediate results. Tasks span ten research themes, with theme sizes determined by available resources and screening outcomes.

\subsection{Sources and Construction}
Tasks are either selected from existing question-answer resources or derived from scientific data. Geoscientific big-data analysis includes 40 selected GeoQuestions1089 tasks involving physical geographic objects and spatial operations. Remote sensing includes 49 of Earth-Bench's 248 tasks, retaining source questions, choices, and answers while adapting calls to our interfaces. Critical-mineral and climate-change tasks are selected from \nolinkurl{habitable_earth_dataset}; underlying resources include MRDS, paleoclimate reconstructions, GISTEMP, and SSP warming summaries. Data-derived tasks specify identifiable objects, variables, and computational relationships, with answers determined through processing and calculation. Table~\ref{tab:benchmark} lists the data sources.

Reference calls map source operational requirements to registered tools and record parameters and input/output information. Existing tasks retain source identifiers or resource locators; derived tasks retain data-location fields, derivation records, and computational scripts. Quality control checks traceability, record completeness, consistency of reference invocations, and sample execution. Sample validation is recorded separately from full-benchmark evaluation and does not establish correctness on all tasks.

\subsection{Composition and Evaluation}
\label{sec:metrics}
The benchmark contains 603 evaluation records: 424 have one reference call, 119 have two or three, and 60 have at least four. Its 179 multistep records constitute 29.68\% of the benchmark. Nine cross-theme questions occur in both critical minerals and climate change, so 603 does not denote 603 distinct questions.

A step denotes one reference tool invocation, rather than one scientific operation or a direct measure of scientific difficulty. Energy-resource and ocean-carbon task wrappers, for example, can perform several operations internally. Chain-length strata therefore describe orchestration demands under the current interfaces. A reference chain represents one implementation under the current interfaces. Domain and chain-length groups describe task backgrounds and interface-level workflow composition, respectively.


\paragraph{Final Answer Score (FAS).}
FAS lies in $[0,1]$ and retains partial credit. Scoring normalizes choices, matches dates and identifiers, applies numerical tolerances, scores matches among multiple values/text items, and compares structured fields. Empty answers receive zero. For $N$ records,
\begin{equation}
\overline{FAS} = \frac{1}{N}\sum_{i=1}^{N}{FAS}_i.
\label{eq:fas}
\end{equation}
The main experiment uses $N=603$. Groups average their own records with failures retained. This is a task-level micro-average, distinct from a domain-balanced macro-average or full-credit rate.

\paragraph{Tool Selection F1 (TSF1).}
Let $G_i$ and $A_i$ be the reference and actual successful-call sequences for task $i$. Treating them as multisets, match calls one to one by tool name, retaining multiplicity. With $m_i$ matches,
\begin{equation}
\mathrm{TSF1}_i=\frac{2m_i}{|G_i|+|A_i|}.
\label{eq:tsf1}
\end{equation}
This is the harmonic mean of precision $m_i/|A_i|$ and recall $m_i/|G_i|$. Missing, irrelevant, and repeated successful calls affect the score.

\paragraph{Tool Order Score (TOS).}
Using the longest common subsequence,
\begin{equation}
\mathrm{TOS}_i=\frac{\mathrm{LCS}(G_i,A_i)}{|G_i|}.
\label{eq:tos}
\end{equation}
For read--filter--count versus read--count--filter, TSF1 is 1 and TOS is $2/3$. Extra calls do not directly reduce TOS, so TSF1 is also needed to assess excess invocations. Both scores are zero when no call succeeds. Failed calls are excluded from successful sequences, but failed tasks remain in the averages. All three metrics use per-task averaging and are reported separately. Subset ablations do not summarize all 603 records.

TSF1 and TOS assess tool coverage and reference order. Matching names and order can still conceal wrong parameters or artifact consumption. Execution traces and computational results are therefore required; a different valid workflow is not a failure solely because its process metrics are lower.
