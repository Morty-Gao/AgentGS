\subsection{Hierarchical Representation and Skill Hypergraphs}
\label{sec:representation}
A \emph{Skill} is a reusable task strategy with an objective, applicable inputs, expected artifacts, capability steps, constraints, validation requirements, and recovery policies. Each step specifies a Capability, mandatory predecessors, optional or mandatory status, and permitted tools. Task-relevant local steps can be selected without importing the entire strategy. New Skills package composed workflows without creating new Capability definitions or Tool implementations.

A \emph{Capability} defines a shared operation: its function, input and output types, preconditions, postconditions, and candidate tools. Sharing does not remove strategy-specific constraints; deep-time and carbon-storage Skills may share raster analysis while permitting different implementations. A \emph{Tool} is a callable interface with an identifier, parameter schema, input/output definitions, and runtime information. Concrete resources and artifacts are bound during execution. Skill--Capability membership and Capability--Tool mappings are many-to-many; mappings additionally record operation and parameter constraints.

The task-specific plan uses capability instances:
\begin{equation}
P=(V,D_d,D_c,\beta),\qquad v_i=(c_i,s_i,r_i).
\label{eq:plan}
\end{equation}
Here, $c_i$, $s_i$, and $r_i$ identify the operation, source strategy, and step/input role. $D_d$ and $D_c$ record data and control dependencies, and $\beta$ binds resources or upstream artifacts. Operations on different objects remain distinct instances even when they use the same tool.

The skill hypergraph connects registered Skills through shared Capabilities:
\begin{equation}
H=(C,E),\qquad E=\{e_s:s\in S\},\qquad e_s\subseteq C.
\label{eq:hypergraph}
\end{equation}
Capabilities are nodes and each Skill's capability set is a hyperedge. Skills containing $\{a,b\}$ and $\{b,c\}$ share $b$. Membership alone does not determine execution order; dependency conditions must be expanded. A provenance-bearing relation $d=(s,U,c)$ specifies that $c$ requires all predecessors in $U$ within Skill $s$.
